## 已完成

1. 建立 `src/cardiac_agent/`，按 ROI、Function、RWMA、Knowledge Bridge、Explanation、QA 分层。
2. 支持 ED/ES 图像及人工/预测双 mask，校验前景标签、图像网格、空 mask 和 spacing。
3. 计算 ED/ES 面积、面积比、FAC；保留 normalized intensity difference 基线及可选 Farneback 接口。
4. RWMA 使用独立预测协议；无训练权重返回 unavailable，关键 QC 异常返回 abstained。
5. 结构化 Knowledge Packet 保存指标、来源、mask 引用及 SHA256、预测状态和方法限制。
6. 接入 SiliconFlow 的 `Qwen/Qwen3-30B-A3B-Instruct-2507`；使用服务器现有 RS-Agent `.env`。
7. 首版 Qwen 组织结构化事实，核验后由模板表达；无依据数字、字段异常和接口失败均显式回退。
8. 三项确定性 QA、算术一致性、可选 RWMA 标签准确率和 Dice/IoU/面积误差函数。
9. 运行按 UUID 独立保存，JSON 原子写入，保留失败记录、输入/产物校验和及源码指纹。
10. CAMUS 单病例导入接口，支持 MHD/raw、NIfTI ED/ES 文件，保留多类标注与 spacing。
11. 拉取官方 EchoNet-Dynamic 源码，完成 lazy DeepLabV3-ResNet50 适配器和待配置模板。

## 使用方式

```bash
source /root/miniconda3/etc/profile.d/conda.sh
conda activate cardiac-agent
cd /root/autodl-tmp/Cardiac-Agent
cardiac-agent run data/synthetic-001/study.json --output runs
cardiac-agent run data/synthetic-001/study.json --output runs --qwen \
  --env /root/autodl-tmp/RS-Agent/.env
cardiac-agent verify runs/6632a4d40bde4ffb98322251aca766b9
```

无需新增 API key。新项目的 `.env.example` 列出模型与 endpoint 配置；现有 key 保留在
原项目 `.env` 中，由 `--env` 读取，不写入新源码、测试、运行产物或备份。

环境清单：`requirements.cpu.lock.txt`、`conda.cpu.linux-64.explicit.txt`。
重建环境时，pip 清单中的 editable 本地路径需替换为当前项目路径。
